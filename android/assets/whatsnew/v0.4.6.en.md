This is a security release; please update soon. The issues came from a code audit and centre on HTML preview: opening an untrusted web page inside the app let it do more than it should.

## Fixes

- **Preview pages could read other files.** Previewing an HTML file on shared storage let its scripts climb parent folders and read all of shared storage, including photos and downloads. A preview page can now only read its own folder and the few parent levels fixed when the preview opens, and never the storage root or broad folders such as Download or DCIM. Pages that load `../assets` from a parent folder still work.
- **Preview pages could call the app's native functions.** Scripts in a preview could call uninstall, write to the clipboard or open links directly. These functions now require a key that is only given to the app's own interface, which preview pages can't get.
- **One malformed request could stop the gateway.** Any app on the device could crash the gateway with a specially crafted request. Such requests now get an error and the gateway keeps running.

## Hardening

- Downloads of Claude Code from the official source now also verify Anthropic's signature instead of relying on HTTPS alone. Older versions without a signature file fall back to the npm signature and still install.
- The interface WebView no longer has access to local files (file://).
- The in-app browser recognises local addresses more strictly, including forms like `127.1` and `2130706433`.
- The GitHub Actions used for builds are now pinned to specific commits.
